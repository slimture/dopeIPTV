Add this line inside the existing `map $server_name $csp_policy { ... }` block
in the TLS-front proxy's /usr/local/etc/nginx/nginx.conf (next to your main site row):

    "dopeiptv.org" "default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';";

Why this is safe AND sufficient for the site:
  - default-src 'self'      everything same-origin by default
  - img-src 'self' data:    screenshots + the SVG favicon (data: covers inline SVG use)
  - style-src 'self'        external style.css only (no inline styles -> no 'unsafe-inline')
  - script-src 'self'       external nav.js and friends; the JSON-LD block is a
                            non-executable data block and is NOT affected by script-src
  - connect-src 'self'      the site's own calls (/support/key, /feedback/, /hit);
                            everything else is same-origin <a> links
  - object/base/form locked down

Nothing from Stripe is loaded on the site any more: a tip and monthly support
are Stripe's own pages (Payment Links), reached by a plain link, which a CSP
does not govern. Until November 2026 the donate dialog loaded Stripe.js and
its frames, and this row allowed js.stripe.com, api.stripe.com, Stripe's
frames and Google Pay's - take those out of an older row.

The global add_header Content-Security-Policy $csp_policy already applies it, so no
per-server add_header is needed.
