1. Error reports and feedback

Nothing that points to you or to what you watch leaves your computer in an error report – and nothing leaves at all until you press Send.

How it works

  1. The app writes the report and cleans it on your computer.
  2. You read all of it, change or delete anything, and decide whether to send it.
  3. Our server cleans it once more and keeps it without your IP address.

The cleaning works in two ways. First it looks for patterns: anything shaped like a web address, an IP or MAC address, an e-mail address, or a password, token or login written as name=value. Then it removes what the app knows is yours: the names, servers and logins of your sources, your channel names, the titles you have watched, your user name and your home folder. Each is replaced by a placeholder such as <private>, so the report still makes sense to us without saying who you are.

If you ask for an answer, the app makes a random code that stays on your computer and sends only a hash of it – a one-way fingerprint we cannot turn back into the code. Later the app asks whether that hash has an answer. Nothing in it says who you are.

What it does not protect against

  • The cleaning knows patterns and what the app knows is yours. Words you type yourself in a piece of feedback, or a name it has never seen – a file name, a channel from a list you have since removed – stay as they are. That is why you see the whole report before anything is sent.
  • Our server's second cleaning is simpler than the app's: it does not know your names, and it does not look for IPv6 addresses. It is there for an old app or a hand-made request; the app's cleaning is the one that counts.
  • Like every request on the internet, the report arrives from your IP address. Our server uses it only in memory, for at most a day, to limit how many reports one address can send, and never stores it.

2. Settings sync

What you sync is locked on your computer before it is sent, with a key we never see – we keep it, but we cannot read it or tell whose it is.

How it works

  1. Your computer makes a random sync code – 256 bits, shown as 13 groups of four.
  2. From the code come two unrelated values: a slot (where the copy is kept) and a key (which locks it).
  3. Our server gets the slot and the locked copy. Never the code, never the key.

The two values come from the code through HKDF-SHA256, a standard way to make several keys from one secret: knowing the slot says nothing about the key. The copy is compressed and then encrypted with ChaCha20-Poly1305, one of the ciphers that protect HTTPS connections on the web. It also detects any change: a copy someone has tampered with does not open. Your other computers get the same code from you – typed or pasted – and so make the same slot and key.

The request carries the app's name and version, whether it is an official build, the slot and the locked copy. No account, no e-mail address, no name. The web server does not log sync requests at all, and a copy no computer has read or written for 180 days is deleted.

3. Watch together

Who is in the room and what you watch go between your computers locked – our server only passes on messages it cannot open.

How it works

  1. The room code – eight characters you share with your friends – stays with the people in the room.
  2. From the code each computer makes the same room name and the same key.
  3. Our server passes the locked messages on, keeps them only in memory, and forgets the room an hour after the last request.

Eight characters are quick to type, but on their own they would be quick to guess. So the code is first stretched with PBKDF2 – 120,000 rounds of SHA-256, which makes every guess slow – and then turned into a room name and a key with HKDF, as for sync. Each message – who joined, what plays, play, pause and seek – is encrypted with ChaCha20-Poly1305 and padded to one of four fixed sizes, so its length says little about what is in it. Each person gets a new random number for each room.

4. Private viewing

While private viewing is on, nothing you play is kept on your computer or told to anyone – until you close the app.

How it works

  1. One switch in the app's memory – never saved, so it is off again when the app starts.
  2. Each place that keeps something – watch history, where you stopped – asks the switch itself before it writes.
  3. Each place that tells – Trakt, Simkl, Discord, your media server, the statistics, the log – asks it too.

The check sits in the stores themselves, not in the buttons that play something. So no part of the app can forget it: whichever way you start a film, the history refuses to write it. A playback that began in private stays private to its end – even if the stream reconnects after you turn private viewing off.

5. Looking for updates

When the app looks for an update it says which app and version it is, on which system – and nothing else.

How it works

Once a day the app asks dopeiptv.org which version is the newest (GitHub, if we do not answer). The request carries a user agent and one more line saying whether this is an official build. That is all: no ID, no settings, nothing about what you watch.

An update is never used just because it arrived. Every release comes with a list of its files' checksums, signed with our own release key. The app checks the signature and the file's checksum before it installs anything. Someone who could change a file on GitHub, but does not hold our key, cannot get an update into your app.

6. This website's statistics

We count visits without cookies, without outside services and without keeping your IP address in the statistics.

How it works

  1. The web server writes each request in a log – with the IP address. The log is deleted after about a week.
  2. Every 15 minutes the log is read: the address becomes a country (looked up on our own server) and a visitor ID, and is not written further.
  3. After 400 days a visit loses its ID, the time of day and the screen size. Only anonymous figures remain.

The visitor ID is a hash: the IP address and the browser's name run through SHA-256 together with a secret that exists only on our server, cut to twelve characters. The same visitor gets the same ID, so we can count unique and returning visitors – but the ID cannot be turned back into the address.

8. How you know the app runs this code

The app you download is built from exactly this code, in public, and it can tell when it has been changed.

  • Built in public. Every release is built by GitHub Actions from the version's tag in the code – not on our computers. The build's recipe is in the code, and the log of every build is open to anyone.
  • Signed. The release's files are listed with their checksums, and the list is signed with our release key. The app checks an update against it, and this website checks every file it hands out against it too.
  • It checks itself. The app carries a signed list of its own files and checks them when it starts. A changed copy knows it is changed, and does not use our services: it looks for no updates here and sends no reports to us.

You can also run the tests yourself, or run the app straight from the code:

git clone https://github.com/slimture/dopeIPTV
cd dopeIPTV
git checkout %REF%
python3 -m pip install -r requirements.txt pytest
QT_QPA_PLATFORM=offscreen python3 -m pytest tests/test_report.py
